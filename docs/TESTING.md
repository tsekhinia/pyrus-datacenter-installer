# Проверки v0.1.0

Дата: 20.10.2026. Поддерживаемый контракт: официальный Pyrus Compose 1.27.0.

## Выполнено

- `bash -n` для главного скрипта и каждого модуля.
- ShellCheck 0.9.0 без замечаний.
- Компиляция всех Python-модулей стандартным `py_compile`.
- Реальный Docker Compose V2 2.40.3: нормализация скачанного официального YAML,
  преобразование и повторная валидация генерируемого Compose для MinIO и внешнего S3.
- Тесты конфигурации: обязательные значения, hostname, email, SMTP, S3,
  права входного файла, недопустимые переносы строк, отсутствие исполнения
  shell-подстановок из паролей, удаление временных секретов и фильтрация журнала.
- Тесты контракта Compose: набор сервисов, версии образов, зависимости,
  сохранение healthcheck, совпадение пароля БД во всех подключениях,
  отсутствие ClickHouse/Госключа в обычном запуске, MinIO только при выборе MinIO.
- Исполнение настоящего `main()` с имитацией Docker daemon: успешная установка,
  повторный запуск без переинициализации, прерванное создание БД, продолжение
  после ошибки SMTP, запрет изменённого Compose и подменённой БД,
  отказ при неверном сертификате или новом upstream hash, план без изменений,
  отказ для удалённого Docker, существующих ресурсов и таймаут готовности.

В тестах используются временные каталоги и сгенерированные тестовые сертификаты.
Вызовы Docker записываются тестовым исполняемым файлом; секреты шаблона не являются
настоящими. Изменение sysctl, реальный запуск контейнеров и применение лицензии
не выполняются. Файл fixtures — снимок для проверки совместимости, не поставка
собственного Compose вместо официального файла.

## Не проверено

Полная установка лицензированного Pyrus на настоящую VM, доступ в интерфейс,
реальная доставка SMTP и загрузка/скачивание файлов через S3. Среда разработки
не предоставляет Docker daemon и рекомендованные для ДЦ ресурсы. Поэтому
v0.1.0 нужно сначала запускать на новой тестовой VM.

Для завершения проверки:

1. Подготовьте новый сервер Ubuntu 22.04/24.04 amd64 с Docker и Compose V2,
   DNS, сертификатом, лицензией и SMTP.
2. Выполните `--preflight`, затем установку; сохраните закрытый журнал.
3. Проверьте все контейнеры командой `--check`.
4. С рабочей станции войдите в Pyrus и проверьте уведомление/код по почте.
5. Создайте задачу, загрузите файл, скачайте его, проверьте поиск.
6. Повторите `--resume`: изменения и повторная инициализация не ожидаются.
7. Перезагрузите тестовую VM, снова проверьте вход, вложение и `--check`.

Не используйте существующий production-сервер для первой проверки.
