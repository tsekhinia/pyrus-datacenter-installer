# Проверки v0.1.0

Дата: 20.10.2026. Поддерживаемый контракт: официальный Pyrus Compose 1.27.0.

## Выполнено

- `bash -n` для главного скрипта и каждого модуля.
- ShellCheck 0.9.0 без замечаний.
- Компиляция всех Python-модулей стандартным `py_compile`.
- Реальный Docker Compose V2 2.40.3: нормализация скачанного официального YAML,
  преобразование и повторная валидация генерируемого Compose для MinIO и внешнего S3.
- Тесты конфигурации: обязательные значения, hostname, email, SMTP, S3,
  права входного файла, недопустимые переносы строк, отсутствие исполнения
  shell-подстановок из паролей, удаление временных секретов и фильтрация журнала.
- Тесты контракта Compose: набор сервисов, версии образов, зависимости,
  сохранение healthcheck, совпадение пароля БД во всех подключениях,
  отсутствие ClickHouse/Госключа в обычном запуске, MinIO только при выборе MinIO.
- Исполнение настоящего `main()` с имитацией Docker daemon: успешная установка,
  повторный запуск без переинициализации, прерванное создание БД, продолжение
  после ошибки SMTP, запрет изменённого Compose и подменённой БД,
  отказ при неверном сертификате или новом upstream hash, план без изменений,
  отказ для удалённого Docker, существующих ресурсов и таймаут готовности.

В тестах используются временные каталоги и сгенерированные тестовые сертификаты.
Вызовы Docker записываются тестовым исполняемым файлом; секреты шаблона не являются
настоящими. Изменение sysctl, реальный запуск контейнеров и применение лицензии
не выполняются. Файл fixtures — снимок для проверки совместимости, не поставка
собственного Compose вместо официального файла.

## Запуск одной командой

Добавлен `bootstrap.sh`: скачивает архив закреплённого коммита установщика,
проверяет SHA-256 до распаковки и запускает полный комплект во временном каталоге.
Для обновления поставляемого кода нужно осознанно заменить `INSTALLER_COMMIT`
и `ARCHIVE_SHA256` вместе после проверки новой версии. Ранее сохранённый загрузчик
продолжает использовать закреплённую версию, в том числе при `--resume`.

Шесть офлайн-сценариев `tests/test_bootstrap.py` проверяют:

- скачивание через curl и работу на сервере, где есть только wget;
- передачу параметров без потери пробелов и закреплённый URL архива;
- остановку до выполнения кода при HTTP-ошибке или несовпадении SHA-256;
- сохранение кода возврата основного установщика и очистку временных файлов;
- запуск через pipe с настоящим псевдотерминалом: мастер читает ответ с терминала.

Живой публичный архив получен по закреплённому URL; SHA-256 совпал с загрузчиком.
Это проверка доставки кода, полная установка на VM по-прежнему требует проверки.

## Управление конфигурационными параметрами

`tests/test_parameters.py` проверяет меню через настоящий псевдотерминал:
открытый и скрытый ввод, подтверждения чтения секретов, запись значений с
пробелами и shell-символами без исполнения, отмену, неверные ID/значения,
ошибки чтения/записи, обновление только открытых полей снимка, EOF и перезапуск
только приложения. Проверяются сохранение отметки при ошибке перезапуска,
отсутствие новых секретов в JSON и журналах и запрет домена вне TLS-сертификата.

Сценарии `main()` дополнительно проверяют явный `--menu` и автоматическое
открытие меню завершённой установки, отсутствие переинициализации и новых
журналов, запрет меню до завершения установки, конфликтующих режимов,
перенаправленного вывода и изменённого Compose.

Для меню используются документированные команды `--setup -ls`,
`--setup -ls -id ID` и `--setup -id ID -v VALUE`. Их вывод намеренно не разбирается:
формат и служебные строки CLI могут отличаться между сборками. Чтение через
настоящий `pyrus-setup`, изменение параметров и перезапуск лицензированного
Pyrus на VM требуют отдельной проверки.

## Подключение к существующему Pyrus

Сценарии `tests/test_existing.py` запускают настоящий `main()` и меню в
псевдотерминале с имитацией старого Docker без команд `docker compose` и
`docker-compose`. Проверяются обнаружение проекта без `.installer`, выбор из
нескольких проектов, чтение и скрытая запись параметров, передача реального
окружения БД без секретов в argv/файлах, локальный неизменяемый образ нужной
версии, отказ при отсутствии или несовпадении образа, остановленной БД,
удалённом Docker и неоднозначной сети. Проверяются перезапуск только приложения,
очистка временных метаданных, блокировка и запрет операций инициализации.

Новая установка сохраняет требования Docker Engine 24+ и Compose V2 2.24+.
Эти требования не переносятся на режим подключения к существующим контейнерам.
Реальные команды `pyrus-setup` на старом сервере и нестандартные схемы с внешней
БД/несколькими экземплярами `web-api` по-прежнему требуют отдельной проверки.

## Не проверено

Полная установка лицензированного Pyrus на настоящую VM, доступ в интерфейс,
реальная доставка SMTP и загрузка/скачивание файлов через S3. Среда разработки
не предоставляет Docker daemon и рекомендованные для ДЦ ресурсы. Поэтому
v0.1.0 нужно сначала запускать на новой тестовой VM.

Для завершения проверки:

1. Подготовьте новый сервер Ubuntu 22.04/24.04 amd64 с Docker и Compose V2,
   DNS, сертификатом, лицензией и SMTP.
2. Выполните `--preflight`, затем установку; сохраните закрытый журнал.
3. Проверьте все контейнеры командой `--check`.
4. С рабочей станции войдите в Pyrus и проверьте уведомление/код по почте.
5. Создайте задачу, загрузите файл, скачайте его, проверьте поиск.
6. Повторите `--resume`: изменения и повторная инициализация не ожидаются.
7. Перезагрузите тестовую VM, снова проверьте вход, вложение и `--check`.
8. Откройте `--menu`, сверьте SMTP с выводом `--setup -ls -id 101301`.
   Отмените пробную запись; затем сохраните прежнее корректное значение,
   перезапустите приложение через пункт 5, проверьте `--check` и доставку почты.

Не используйте существующий production-сервер для первой проверки.
